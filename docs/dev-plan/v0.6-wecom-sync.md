# Inspect Lab v0.6 · 企微智能表格单向同步实施方案

- 状态：开发完成，待真实租户联调
- 方案：智能表格「接收外部数据」Webhook，插件 background 直连，单向上报
- 前置结论：文档 API 直连不可行（secret 下发、企业可信 IP、仅能编辑应用自建文档）；Webhook 无应用/secret/可信 IP/管理员审批门槛，且能写入已有表格
- 不在本期范围：读取表格、双向同步、状态回写、多人协作、批量上报、自建服务端

---

## 1. 目标与边界

**目标**：在评论上点一次「同步到企微」，把该条评论作为一行记录写入指定智能表格工作表；同步中/成功/失败在插件内可见，失败可重试。

**边界**：

- 只写不读，表格里的状态变化不回传插件。
- 一个插件实例配置一个 Webhook + 一套字段映射，不路由到多张表。
- 不引入企业微信应用、corpsecret、文档 API access_token。
- 不保证网络超时场景下的绝对不重复（Webhook 无幂等键）。
- 不改动现有评论的创建、定位、解决逻辑。

**口径变更（2026-11-17）**：评论的「清除」改为**归档**，不真删。归档只打 `archived` 标记并把评论从气泡 / 列表隐藏，保留 `reportedAt` 与 `remoteRecordId`；同步时只上报从未成功上报过的评论。这样即使评论被清除后又被重建，也不会因为丢失上报记录而重复写行。

## 2. 架构与消息链路

```
[页内评论弹层 / 评论列表 / 工作区评论列表]
        │  用户点击「同步到企微」
        ▼
[content script] syncComment(id)
        │  chrome.runtime.sendMessage({ type: 'WECOM_SYNC_COMMENT', thread, context })
        ▼
[background service worker]
        │  1. 读配置 chrome.storage.local['delab-wecom-config']
        │  2. 校验 webhook / FIELD_ID / 必填字段
        │  3. 组装 add_records payload
        │  4. fetch(webhook, { method:'POST', signal: AbortController })
        ▼
[qyapi.weixin.qq.com /cgi-bin/wedoc/smartsheet/webhook?key=…]
        │  { errcode: 0, errmsg: 'ok', add_records: [{ record_id }] }
        ▼
[background] 返回 { ok, recordId } / { ok:false, code, message, retryable }
        ▼
[content script] patchThread({ reportState, reportedAt, remoteRecordId, lastReportError })
        │  refreshCommentsUI() → 气泡 / 列表 / 工作区同步刷新
        ▼
[面板 UI] 同步中 → 已同步 / 同步失败（重试）
```

要点：

- **必须由 background 发起 fetch**。content script 的请求受页面 CORS 约束；background 在 `host_permissions` 下跨域请求不受 CORS 限制。
- 当前 manifest 已有 `host_permissions: ["https://*/*"]`，**无需新增主机权限**；配置页只允许 `https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook`，避免把数据发往任意地址。
- 配置页与测试请求也走 background，页面本身不发网络请求。

### 2.1 消息契约

```ts
// content script / workspace → background
type WecomSyncMessage = {
  type: 'WECOM_SYNC_COMMENT';
  thread: CommentThread;
  context: {
    pageTitle: string;
    viewport?: { width: number; height: number };
  };
};

type WecomTestMessage = {
  type: 'WECOM_TEST';
  config?: WecomConfig; // 配置页未保存时可直接带草稿测试
};

// background → 调用方
type WecomSyncResult =
  | { ok: true; recordId: string | null }
  | { ok: false; code: string; message: string; retryable: boolean };
```

`sendResponse` 需要在监听器里同步返回 `true`，等待异步 fetch 完成；Service Worker 被回收时请求随之中断，前端按失败处理。

## 3. CommentThread 数据结构改动

现有定义见 [comment-store.ts](../../src/comment-store.ts#L5-L16)。新增字段全部可选，旧数据无需迁移：

```ts
export type ReportState = 'idle' | 'pending' | 'synced' | 'failed';

export interface CommentThread {
  id: string;
  page: string;
  url: string;
  identity: ElementIdentity;
  body: string;
  resolved: boolean;
  createdAt: number;
  snapshot?: string;

  // v0.6 新增
  /** 最近一次上报状态；pending 不持久化，仅内存态 */
  reportState?: 'synced' | 'failed';
  /** 首次上报成功时间 */
  reportedAt?: number;
  /** 企微返回的 record_id，用于展示与后续人工排查 */
  remoteRecordId?: string;
  /** 最近一次失败的错误码与信息，成功后清空 */
  lastReportError?: { code: string; message: string; at: number };
  /** 已尝试次数，用于 UI 与排障 */
  reportAttempts?: number;

  // v0.6 归档（「清除」不真删）
  /** 已清除：气泡与列表都不再展示，数据保留 */
  archived?: boolean;
  /** 清除时间 */
  archivedAt?: number;
}
```

`patchThread` 的 patch 类型需要扩展：

```ts
Partial<Pick<CommentThread,
  | 'resolved' | 'body'
  | 'reportState' | 'reportedAt' | 'remoteRecordId' | 'lastReportError' | 'reportAttempts'
  | 'archived' | 'archivedAt'
>>
```

**不持久化 `pending`**：页面刷新或 Service Worker 重启后不会出现永远转圈的记录；重载后按 `reportState` 显示已同步或可重试。

`CommentsView` 的过滤条件为 `!resolved && !archived`，已同步评论继续留在列表，避免“同步后消失”。

### 3.1 清除即归档

- 新增 `archiveThread(page, id)`：只写 `archived: true` 与 `archivedAt`，不调用删除、不清空数组。
- 原先的 `removeThread()` 移除，避免任何路径真删评论。
- 气泡（`renderPins`）、侧边栏 / 工作区列表、评论计数、`toMarkdown` 全部按 `!resolved && !archived` 过滤。
- `reportedAt` / `remoteRecordId` / `reportAttempts` 原样保留；即使评论被归档，历史上报信息仍在。
- 同步入口只对 `reportedAt == null` 的评论开放；已上报过的评论即使被重建（同 id）也不会再写一行。新评论是新 id，不受影响。
- 弹层头部新增归档图标（清除）；归档二次确认后关闭弹层。侧边栏 / 工作区列表只展示未解决、未归档评论，因此不单独放归档按钮。

## 4. 配置模型与存储

### 4.1 类型

```ts
export type WecomFieldKey =
  | 'commentId' | 'body' | 'url' | 'pageTitle' | 'site'
  | 'selector' | 'domPath' | 'elementText' | 'component'
  | 'createdAt' | 'snapshot' | 'status' | 'reporter';

export interface WecomConfig {
  version: 1;
  enabled: boolean;
  webhookUrl: string;
  fields: Partial<Record<WecomFieldKey, string>>; // FIELD_ID
  includeSnapshot: boolean;
  stripQuery: boolean;      // URL 去掉 query/hash，默认 true
  reporter?: string;        // 可选：企微成员姓名/别名
  timeoutMs: number;        // 默认 10000
}
```

### 4.2 存储

- key：`delab-wecom-config`
- 位置：`chrome.storage.local`（与评论同源，扩展内所有上下文可读）
- 保存时机：配置页点「保存配置」；输入过程不自动写
- 敏感处理：Webhook URL 是写权限凭证，UI 默认脱敏展示；日志永不输出完整 URL

示例：

```json
{
  "version": 1,
  "enabled": true,
  "webhookUrl": "https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=QIik…",
  "fields": {
    "commentId": "fld_comment_id",
    "body": "fld_body",
    "url": "fld_url",
    "pageTitle": "fld_page_title",
    "site": "fld_site",
    "selector": "fld_selector",
    "domPath": "fld_dom_path",
    "elementText": "fld_element_text",
    "component": "fld_component",
    "createdAt": "fld_created_at",
    "snapshot": "fld_snapshot",
    "status": "fld_status",
    "reporter": "fld_reporter"
  },
  "includeSnapshot": true,
  "stripQuery": true,
  "reporter": "",
  "timeoutMs": 10000
}
```

### 4.3 配置校验

保存与上报前都要校验：

- URL 必须 `https:`，host 必须 `qyapi.weixin.qq.com`，path 必须是 `/cgi-bin/wedoc/smartsheet/webhook`，必须带非空 `key`。
- `body`、`commentId`、`url` 三个 FIELD_ID 必填；其余可空，空则跳过该列。
- FIELD_ID 去重检查：同一个 ID 不能映射到多个字段，避免互相覆盖。
- `timeoutMs` 限制在 3000–30000。
- 任何校验失败都不发请求，直接返回配置错误。

## 5. 智能表格侧字段映射

建议在表格中预建以下字段（字段类型必须匹配，否则写入报错）：

| 字段标题 | 类型 | 是否必填 | 来源 | 说明 |
| --- | --- | --- | --- | --- |
| 评论ID | 文本 | 是 | `thread.id` | 幂等辅助 / 人工排查 |
| 评论内容 | 文本 | 是 | `thread.body` | 超长截断 |
| 页面链接 | 链接 | 是 | `thread.url` | 可去除 query |
| 页面标题 | 文本 | 否 | 上报时 `document.title` | 需补采 |
| 站点 | 文本 | 否 | `thread.page` | origin |
| 元素选择器 | 文本 | 否 | `identity.selector` | |
| DOM 路径 | 文本 | 否 | `identity.path` | |
| 元素文案 | 文本 | 否 | `identity.text` | ≤60 字 |
| 组件 / 源码 | 文本 | 否 | `component` + `source` | 仅 dev 可得 |
| 评论时间 | 日期 | 否 | `createdAt` | 传毫秒时间戳字符串 |
| 截图 | 图片 | 否 | `snapshot` | 去掉 dataURL 前缀，传 `image_base64` |
| 状态 | 单选 | 否 | 固定「待处理」 | 不回读 |
| 上报人 | 文本 | 否 | 配置里的姓名 | 按姓名原文写入；不要映射到成员类型字段 |

**不可写字段**：公式、自动编号、查找引用、创建人/创建时间、最后编辑人/最后编辑时间、群聊、文件。不要把评论时间映射到「创建时间」类型字段。

## 7. 配置页内容

页面结构（单列，宽 640–720px）：

1. **连接状态**
   - Webhook 输入框（默认脱敏，点击眼睛显示全文）
   - 状态徽标：未配置 / 已保存 / 连接正常 / 最近一次失败
   - 「发送测试记录」按钮 + 结果区（成功显示 record_id，失败显示错误码与原因）
2. **字段映射**
   - 13 行：字段名、表格字段类型、FIELD_ID 输入、是否必填
   - 顶部说明：FIELD_ID 从智能表格「接收外部数据 → 示例数据」中复制
   - 校验：必填、重复、空值
3. **上报选项**
   - 包含截图（默认开）
   - 页面链接去除 query/hash（默认开）
   - 上报人（可选，文本）
   - 超时（默认 10 秒）
4. **安全与说明**
   - Webhook 等同写权限，仅存本机；泄露后到表格里停用并重建
   - 单向上报，不读取表格
   - 不写入公式/创建时间等字段

保存按钮写入 `chrome.storage.local`；测试按钮发送一条固定测试记录（`评论ID = test_<时间戳>`，正文「Inspect Lab 连接测试」），**不进评论列表**。

## 8. 错误与重试策略

### 8.1 错误分类

| 类别 | 判定 | 是否可重试 | UI 处理 |
| --- | --- | --- | --- |
| 未配置 / URL 非法 | 本地校验 | 否 | 引导去配置页 |
| FIELD_ID 缺失 / 重复 | 本地校验 | 否 | 标红对应映射 |
| key 失效 / Webhook 已停用 | 企微返回鉴权错误 | 否 | 提示重新生成 Webhook |
| 字段不存在 / 类型不匹配 | 企微返回参数错误 | 否 | 提示检查字段映射，修复后重试 |
| 触发限流 | 企微返回频率错误 | 是 | 延迟后手动重试 |
| 网络错误 / 超时 | fetch reject / AbortError | 是 | 显示「重试」 |
| 5xx / 响应非 JSON | HTTP 状态或解析失败 | 是 | 显示「重试」 |

具体 errcode 以企微实际返回为准，代码里维护映射表，未知码原样展示 `errcode + errmsg`。

### 8.2 重试

- **默认只手动重试**，不做指数退避自动重试：Webhook 没有幂等键，自动重试会放大重复行风险。
- 单次请求超时 10 秒（可配 3–30 秒），用 `AbortController` 中止。
- 重试复用同一条记录（同 `commentId`），成功后清空 `lastReportError`。
- 连续失败 3 次后，UI 提示检查配置/网络，不再频繁请求。

### 8.3 防连点

- 内存中维护 `syncingIds: Set<string>`；正在上报或已 `synced` 时按钮禁用。`pending` 只存在内存，不落库。
- 已同步记录默认不再上报；如需重新上报，走二次确认（v0.6 可不做）。

## 9. 幂等与去重

Webhook 没有业务唯一键，分三层处理：

1. **本地状态机**：`idle → pending → synced / failed`，成功即落 `reportedAt` + `remoteRecordId`，按钮变「已同步」。`pending` 只存在内存，不落库。
2. **只发未上报过的评论**：入口与发送前都检查 `reportedAt == null`；已上报过的评论（含已归档的）直接跳过，避免清空后重建导致重复行。
3. **归档不清数据**：`archived` 只影响展示，`reportedAt` / `remoteRecordId` 永久保留，重建同 id 评论时仍视为已上报。
4. **评论ID 列**：每行都写入 `thread.id`，表格侧可用公式/自动化标出重复，便于人工清理。
5. **不自动重试**：超时场景可能“服务端已写入但客户端没收到”，这是已知残留风险；重试前 UI 提示「上次可能已写入，请先在表格确认」。

后续如需强幂等，引入中转服务，用 `commentId` 做唯一键（本期不做）。

## 10. 日志与脱敏

- 允许记录：`commentId`、`errcode`、`errmsg`、耗时、HTTP 状态。
- 禁止记录：完整 Webhook URL、`key`、截图 base64、评论正文全文。
- URL 统一走 `maskWebhook()`：保留 host/path，`key` 只显示前 4 位与后 4 位。
- 错误上报只带错误码与字段 key 名，不带值。
- 实际实现只写 `console.debug` / `console.info`：成功记耗时与 record_id，失败记错误码与耗时；不输出 URL、key、正文、截图。

## 14. 企业微信侧一次性准备

1. 新建或在现有智能表格中建好第 5 节的字段；类型必须匹配，避免公式/自动编号/创建时间等不可写类型。
2. 打开目标工作表菜单 →「接收外部数据」→ 开启，选择目标工作表。
3. 复制生成的 Webhook 地址（`https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=…`）。
4. 从「示例数据」里抄下每个字段的 FIELD_ID，填入配置页。
5. 权限：能编辑该工作表即可开启；不要把 Webhook 发到公开渠道。
6. 如出口 IP 固定，可开启来源 IP 白名单；设计师分散办公时不要开，否则请求会被拒。
7. 泄露处理：在「接收外部数据」设置中停用该工作表的 Webhook，重新生成并更新配置。
8. 可选：用表格自动化做「新记录 → 群消息提醒」，替代插件发群消息。
9. 用 curl 先验证一次：

```bash
curl 'https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=KEY' \
  -H 'Content-Type: application/json' \
  -d '{"add_records":[{"values":{"FIELD_ID":[{"type":"text","text":"Inspect Lab 连接测试"}]}}]}'
```

## 15. 风险与未决问题

**已知风险**

- Webhook URL 是 bearer 凭证，配置页必须脱敏、可替换；不要硬编码共享 URL。
- 无幂等键：超时重试可能重复；用评论ID 列辅助人工去重。
- FIELD_ID 在字段删除重建后会变化，配置会失效。
- 只写不读：解决状态、处理人不会回传。
- 截图 base64 可能较大，Webhook 请求体上限官方未给出，需用真实租户验证。
- 页面 URL 可能含 token，默认去 query；截图可能含用户数据，需要产品确认默认开关。

**待实测**

- 普通文档编辑者能否开启「接收外部数据」。
- 单条请求体（含 360px JPEG）的大小上限。
- 文本单元格长度上限。
- 响应中 `record_id` 是否稳定返回。
- 目标企业客户端版本与功能灰度情况。
