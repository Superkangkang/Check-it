## 2. 缺陷清单（仅记录，未修复）

### BUG-1 ｜ M5-06 ｜ Esc 撤销本次修改失效 ｜ 高

- 复现：锁定元素 → 聚焦 font-size 输入框（16px）→ 输入 20 → ↑（21）→ Shift+↓（11）→ 按 Esc → 元素仍为 11px，预期恢复 16px。
- 根因：`PropertyField` 的 Escape 处理先 `commit(original)` 还原，再**同步调用 `blur()`**；`handleBlur` 无条件 `commit(draft)`，此时闭包内 draft 仍是过期值（'11'），把撤销覆盖回去了。
- 代码：[PropertyField.tsx#L68-L75](../../src/components/PropertyField.tsx)（handleBlur）、[PropertyField.tsx#L91-L98](../../src/components/PropertyField.tsx)（Escape 分支）
- 连带影响：M5-02 的验证需在 Esc 污染后的状态下独立对比（非法值拒绝本身行为正常）。

### BUG-2 ｜ M3-06a/b ｜ 悬停框残留 ｜ 低

- 复现：悬停某元素出现悬停框 → 鼠标移到 body 空白处或插件面板上 → 旧悬停框不清除，残留在上一个元素位置。
- 根因：`handleMouseOver` 对 body/html 与插件 UI 分支直接 `return`，未隐藏上一个悬停框。
- 代码：[content-script.ts#L265-L275](../../src/content-script.ts)

### BUG-3 ｜ M6-09b ｜ 已解决评论无「重新打开」入口 ｜ 中

- 复现：标记解决后气泡消失；面板评论列表过滤掉已解决项（`comments.filter(t => !t.resolved)`），弹层也随之不可达 → 「重新打开」按钮存在于弹层但无任何入口可触达。
- 与测试计划 M6-09「再点重新打开恢复」不符；与 README v0.5 一致性待对齐（砍需求或补入口）。
- 代码：[CommentsView.tsx#L22-L23](../../src/components/CommentsView.tsx)

### BUG-4 ｜ M7-03 ｜ 走查/评论模式下面板内系统光标被隐藏 ｜ 低（口径待确认）

- 现象：激活期间面板内 `cursor: none`，仅靠绿色 DOM 指针；测试计划预期「插件 UI 内光标正常」。
- 根因：`applyCursor()` 除页面级规则外，还调用 `shadowHost.setCursorHidden(true)` 打开 Shadow DOM 内部的 `cursor: none !important`。
- 影响：面板文本输入框内无 I-beam 反馈。属交互口径问题（Figma 式全局指针 vs 表单可用性），建议产品确认。
- 代码：[shadow-dom.ts#L38-L47](../../src/shadow-dom.ts)、[content-script.ts#L514-L529](../../src/content-script.ts)
